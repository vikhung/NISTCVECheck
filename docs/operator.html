NIST CVE Scanner

Windows 軟體弱點掃描工具 — 操作手冊（CLI 版 & Web 版）

工具簡介

NIST CVE Scanner 是一套 Node.js 命令列工具，能自動掃描 Windows 電腦上已安裝的軟體，並透過 NIST NVD（美國國家漏洞資料庫） 的公開 API 查詢已知 CVE 弱點，最終產出一份 HTML 視覺化報表。

主要功能

  • 直接從 Windows Registry 讀取已安裝軟體清單，無需手動整理
  • 支援讀取外部 JSON 檔案（可由 findSW.ps1 在其他機器產生後傳入）
  • 以 CVSS 嚴重等級、CVE 年份、掃描數量作為過濾條件
  • 比對建議修復版本，自動判斷升級狀態（無須升級 / 需要升級 / 請手動確認）
  • CPE 比對機制，自動過濾與搜尋軟體無關的誤判 CVE，並列出供使用者自行判斷
  • 支援免安裝軟體（Portable），透過 NVD CPE API 精確比對產品識別碼
  • 輸出含儀表板統計、升級摘要、CVE 詳情的單一 HTML 報表

系統需求

項目需求
作業系統Windows 10 / 11（Registry 掃描模式需要）
Node.jsv18.0.0 以上（建議使用 v18 LTS 或更新版本）
網路可連線至 services.nvd.nist.gov（HTTPS 443）
npm 套件不需要，僅使用 Node.js 內建模組
確認 Node.js 版本在終端機執行 node --version，應顯示 v18.x.x 以上。

快速開始

  1. 建立設定檔
    複製 .env.local.example 為 .env.local，填入 API Key 與白名單： 
    NIST_API_KEY=your-api-key-here
WHITELIST=Microsoft,Apple,Google
  2. 執行掃描（使用所有預設值） 
    node scripts/cve-checker.js
    程式將掃描 PC Registry，查詢 HIGH 以上嚴重等級、近 5 年的 CVE。
  3. 查看報表
    掃描結束後，report/ 目錄下會同時產生 HTML 與 JSON 兩個檔案：
    report/vik_result_YYYYMMDD.html（視覺化報表）
    report/vik_result_YYYYMMDD.json（供 team-report.js 讀取）
    以瀏覽器開啟 HTML 檔即可查閱。
預估執行時間以 API Key 模式（每 0.7 秒一筆），20 筆軟體約需 15 秒。掃描數量越多、等待越長；可用 LIMIT 參數限制筆數先行測試。

掃描 PC Registry

不帶 FILE 參數（或傳入 -1）時，程式會從以下三個 Windows Registry 路徑讀取已安裝軟體：

HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*        # 64 位元程式
HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*  # 32 位元程式
HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*        # 目前使用者

讀取欄位：DisplayName（名稱）、DisplayVersion（版本）、Publisher（發行商）、InstallDate、InstallLocation。

注意此模式僅支援 Windows。在其他作業系統上執行會直接報錯退出。

使用 JSON 檔案

將預先產生的軟體清單 JSON 檔案路徑作為第一個參數傳入：

node scripts/cve-checker.js scan.json
node scripts/cve-checker.js C:\Users\USER\Desktop\scan.json HIGH

JSON 檔案格式

{
  "generatedAt": "2026-05-14T12:49:39.741Z",
  "hostname":    "MYPC",
  "username":    "user",
  "softwares": [
    {
      "name":        "Google Chrome",
      "version":     "148.0.7778.97",
      "publisher":   "Google LLC",
      "installDate": "20260508",    // 可為 null
      "installPath": "C:\\Program Files\\Google\\Chrome\\Application"  // 可為 null
    }
  ]
}

softwares 陣列為必要欄位；其他頂層欄位（generatedAt、hostname、username）若省略會以執行當下的系統資訊補充。

findSW.ps1 說明

findSW.ps1 是隨附的 PowerShell 腳本，可在無法直接執行 Node.js 的機器上收集軟體清單，再將產出的 JSON 傳給 CVE Scanner 掃描。

執行方式

# 預設：儲存至 scan.json
powershell -ExecutionPolicy Bypass -File findSW.ps1

# 指定輸出路徑
powershell -ExecutionPolicy Bypass -File findSW.ps1 -OutputPath C:\temp\scan.json

# 指定使用者名稱（預設為 Windows 登入名稱）
powershell -ExecutionPolicy Bypass -File findSW.ps1 -Username john

與 CVE Scanner 搭配使用

  1. 在目標機器執行 findSW.ps1，產生 scan.json
  2. 將 JSON 檔案複製到安裝了 Node.js 的機器
  3. 執行 node scripts/cve-checker.js scan.json
編碼說明findSW.ps1 輸出 UTF-8 無 BOM 格式，Node.js 可直接讀取。CVE Scanner 內建的 Registry 掃描則需 UTF-8 BOM（已自動處理），兩者格式不同但均相容。

彙總多台機器報表 — team-report.js

team-report.js 可將多台機器各自產生的 JSON 掃描結果整合為一份彙總 HTML 報表，適合資安人員或管理者一次掌握整個團隊的軟體弱點狀態。

執行方式

# 讀取 .\team 目錄中所有 JSON，產生彙總報表至 .\report
node scripts/team-report.js

# 或指定自訂 team 目錄路徑
node scripts/team-report.js C:\scans\team

輸出檔案：report/team_YYYYMMDD.html

無需 API Keyteam-report.js 純讀取本機 JSON，不呼叫 NVD API，執行速度極快。

彙總報表 — 工作流程

  1. 各機器個別掃描
    在每台 Windows 機器上執行掃描，產生帶時間戳記的 JSON 結果檔： 
    node scripts/cve-checker.js
# → report\vik_result_YYYYMMDD.json
    若機器無 Node.js，可改用 PowerShell 腳本： 
    powershell -ExecutionPolicy Bypass -File findSW.ps1
# → scan.json（格式與上方相容）
  2. 集中 JSON 檔案
    將所有機器產生的 JSON 複製至執行 team-report.js 的機器上的 .\team\ 目錄（若目錄不存在請自行建立）： 
    .\team\
    alice_result_20260516143000.json
    bob_result_20260516151200.json
    carol_result_20260516160500.json
  3. 產生彙總報表 
    node scripts/team-report.js
# → report\team_YYYYMMDD.html
    以瀏覽器開啟產生的 HTML 即可查看整個團隊的報表。
混用兩種輸入格式cve-checker.js 產生的 JSON 與 findSW.ps1 產生的 JSON 格式相容，可在同一個 team 目錄中混用。

彙總報表 — 內容說明

彙總報表由以下四個區塊組成：

1. Header 儀表板

顯示整體統計：機器總數、有弱點機器數、所有機器的軟體總計、實際掃描數、發現弱點數、CVE 總數。

2. 機器總覽表

每台機器一列，欄位說明如下：

欄位說明
主機名稱點擊可跳轉至該機器的詳細結果區塊
CVE 日期範圍該次掃描的 CVE 篩選年份範圍，格式為 YYYY/01/01~YYYY/MM/DD（例如 2016/01/01~2026/05/16）
軟體總計該機器 Registry 中的軟體總筆數
掃描數實際向 NVD API 查詢的軟體數（已扣除白名單、子元件、重複）
有弱點發現符合篩選條件 CVE 的軟體數
CVE 數該機器所有軟體的 CVE 總筆數
狀態✗ 需升級 / ? 請手動確認 / ✓ 安全

3. 跨機器需升級軟體彙整

列出所有機器中需要升級的軟體，依受影響機器數降序排列。每列顯示軟體名稱、最低安全版本、受影響機器數，以及各台機器的主機名稱與已安裝版本。

4. 各機器詳細結果

每台機器各占一個獨立區塊，包含：

  • 機器 Meta 資訊列：CVE 日期範圍 | 來源 | 最低嚴重度 | 軟體總計 N | 白名單 N | 子元件/重複 N | 掃描 N | 有弱點 N | CVE N
  • 軟體概覽表：列出所有有弱點與無弱點的軟體，顯示已安裝版本、最低安全版本、最高嚴重度、CVE 數、狀態
  • CVE 詳細資訊（可展開）：每個有弱點的軟體各有一個折疊區塊，點擊展開後顯示：
    • CVE ID（點擊連結至 NVD）、嚴重度徽章、CVSS 版本、發布日期
    • CVE 描述文字
    • 安全版本資訊（如有）
    • 底部建議列：✗ 建議升級至 ≥ X.X.X / ✓ 無須升級 / ? 請手動確認
    • ⚠ 可能誤判標記（若 CPE 條目與搜尋名稱不符）
左側色條代表機器狀態紅色 = 有需要升級的軟體；橘色 = 有弱點但無需升級或請手動確認；綠色 = 全部安全。

命令列參數

node scripts/cve-checker.js [FILE] [MIN_SEVERITY] [LIMIT] [MIN_YEAR]

所有參數均為選填，以 位置 區分（非具名參數）。任何參數傳入 -1 代表「使用預設值」。

位置名稱說明預設值
args[0] FILE 軟體清單 JSON 檔路徑；-1 或省略 = 掃描 PC Registry PC Registry
args[1] MIN_SEVERITY 最低 CVE 嚴重等級篩選（LOW / MEDIUM / HIGH / CRITICAL）；-1 = HIGH HIGH
args[2] LIMIT 最多掃描前 N 筆軟體；-1 = 不限 不限
args[3] MIN_YEAR 只顯示該年份（含）之後發布的 CVE；-1 = 當年 −5 當前年份 −5

使用範例

指令說明
node scripts/cve-checker.js掃描 PC，HIGH 以上，近 5 年
node scripts/cve-checker.js scan.json讀 scan.json，其餘預設
node scripts/cve-checker.js scan.json HIGH讀 scan.json，HIGH 以上
node scripts/cve-checker.js -1 HIGH 5PC，HIGH，只掃前 5 筆
node scripts/cve-checker.js -1 CRITICAL -1 -1PC，CRITICAL，不限數量，近 5 年（預設）
node scripts/cve-checker.js scan.json -1 -1 2020讀 scan.json，HIGH，不限，2020 年後

環境設定（.env.local）

所有環境設定集中在工具目錄下的 .env.local 檔案。複製 .env.local.example 為 .env.local 後依需求修改。此檔案不應提交至版本控制（已列入 .gitignore）。

參數預設值說明
NIST_API_KEY （空） NVD API Key。有 Key 時速率限制為每 0.7 秒一筆；無 Key 則 6.5 秒。免費申請：nvd.nist.gov
LOG_LEVEL INFO DEBUG = 顯示除錯用 log（目前為向 NVD 發出的完整 curl 查詢指令）；INFO = 不顯示。
HTTPS_PROXY / HTTP_PROXY （空） 企業網路需透過 Proxy 連線時設定，支援 http://user:pass@host:port。留空 = 直接連線。
PROXY_SKIP_TLS_VERIFY false true = 停用 TLS 憑證驗證（Proxy 做 SSL Inspection、自簽憑證的環境）。
PORTABLE_ENABLE true false = 完全停用 Portable 功能（即使設定了 PORTABLE_N 也不會掃描）。
PORTABLE_ONLY false true = 只掃描 PORTABLE_N 定義的軟體，略過 Registry / JSON 項目（適合只想快速確認特定軟體的情境）。
WHITELIST （空） 逗號分隔的廠牌關鍵字，符合 Publisher 欄位的軟體略過掃描。例如 Microsoft,Apple,Google。
PORTABLE_N （空） 免安裝軟體設定，詳見下節說明。
CACHE_DISABLE false true = 停用本機 CVE / CPE 快取（data/ 目錄），每次都直接查 NVD API。
CACHE_ALIAS_N （空） 格式：canonical|alias1|alias2。讓不同名稱的查詢（如 maven 與 apache maven）共用同一份本機快取。從 0 連續遞增，遇缺口停止。

範例 .env.local

NIST_API_KEY=your-api-key-here
LOG_LEVEL=INFO
PORTABLE_ONLY=false
WHITELIST=Microsoft,Apple,Google

PORTABLE_0=Eclipse IDE|202506|Eclipse Foundation
PORTABLE_1=Apache Maven|3.8.6|Apache Software Foundation
PORTABLE_2=Node.js|24.15.0|OpenJS Foundation

白名單設定

白名單可指定哪些廠牌的軟體不進行 CVE 掃描，大幅減少不必要的 API 查詢。

設定方式（建議）

在 .env.local 中設定 WHITELIST，以逗號分隔廠牌關鍵字：

WHITELIST=Microsoft,Apple,Google

比對規則

  • 比對目標：軟體的 Publisher（發行商） 欄位
  • 不分大小寫：microsoft 可比對 Microsoft Corporation
  • 部分比對：關鍵字是 Publisher 的子字串即符合
  • 符合任一關鍵字即略過

效果

白名單軟體會被完全略過（不消耗 API 查詢次數），並在報表底部的「白名單略過的軟體」區塊中列出，依規則分組顯示。

建議白名單通常可將 Microsoft、Apple、Google 加入白名單，這些廠商的軟體普遍有完善的自動更新機制，且軟體數量多，加入白名單可大幅減少掃描時間。

免安裝軟體設定（PORTABLE_N）

部分軟體（如 Eclipse、Maven、Neo4j）以免安裝方式執行，不會寫入 Windows Registry，無法透過一般掃描偵測到。PORTABLE_N 設定可將這些軟體手動加入掃描清單。

格式

# 格式：軟體名稱|版本|發行商（版本與發行商可省略）
PORTABLE_0=Eclipse IDE|202506|Eclipse Foundation
PORTABLE_1=Apache Maven|3.8.6|Apache Software Foundation
PORTABLE_2=Node.js|24.15.0|OpenJS Foundation
PORTABLE_3=Neo4j Community Edition|2025.05.0|Neo4j Inc

編號從 0 開始連續遞增，遇到第一個缺口即停止讀取。

特性

  • 跳過白名單與子元件過濾：Portable 軟體直接進入查詢階段
  • CPE API 精確比對：每筆 Portable 軟體會先呼叫 NVD CPE API，查找對應的精確產品識別碼（cpe:2.3:a:{vendor}:{product}），再以此識別碼驗證 CVE 是否真的與該軟體相關，大幅減少誤判
  • 計入軟體總計：Portable 軟體會計入報表的「軟體總計」數量

PORTABLE_ONLY 模式

設定 PORTABLE_ONLY=true 後，程式只掃描 PORTABLE_N 定義的軟體，略過 Registry / JSON 中的所有項目。適合只需快速檢查特定免安裝軟體的情境。

速率限制提醒每筆 Portable 軟體需消耗兩次 API 呼叫（CPE 查詢 + CVE 查詢），執行時間約為一般軟體的兩倍。

「? 請手動確認」的常見情境某軟體的 NVD 頁面中，部分 CVE 有明確的「Up to (excluding) X.X」版本範圍，但另一部分 CVE 僅列出特定版本受影響、沒有版本範圍。後者代表 NVD 目前尚未記錄修復版本（可能是漏洞剛被揭露、廠商尚未發布修補，或 NVD 尚未更新資料）。即使已安裝版本滿足前者，整體狀態仍會顯示「? 請手動確認」，提醒使用者手動查閱各 CVE 連結。
最低安全版本的來源從 CVE 的 CPE（Common Platform Enumeration）資料中的 versionEndExcluding（不含，對應 ≥）或 versionEndIncluding（含，對應 >）欄位取得。若一個軟體有多筆 CVE，取所有 CVE 中的最高修復版本作為建議升級目標。

為何會出現「可能誤判」？

  • Portable 軟體：驗證 CVE 的 CPE 條目是否含有精確的 :vendor:product: 識別碼
  • Registry 軟體：驗證搜尋名稱的所有字詞是否出現在 CPE 條目中

若 CPE 存在但完全不符，則該 CVE 被標記為可能誤判，從版本分析中移除。

  • 需要更全面覆蓋時使用 MEDIUM
  • 需要零誤報的精簡報表使用 CRITICAL

誤判處理機制

NVD 的 關鍵字搜尋是全文比對，可能找到與軟體無關的 CVE。例如：搜尋「Maven」可能找到 Jenkins 的 CVE，因為其描述中提到了 Maven 插件。

兩階段關聯性檢查

程式針對 Registry 軟體與 Portable 軟體採用不同的驗證方式：

Portable 軟體（精確 CPE 比對）

  1. 先透過 NVD CPE API 查找軟體對應的精確識別碼（cpe:2.3:a:{vendor}:{product}:*）
  2. 對每筆 CVE 驗證其 CPE 條目是否包含 :{vendor}:{product}: 字串
  3. 未出現者判定為可能誤判

Registry 軟體（關鍵字比對）

  1. 從 CVE 的 configurations 中提取所有 CPE 條目字串
    （格式範例：cpe:2.3:a:google:chrome:54.0.2840.87:*）
  2. 將搜尋名稱拆解為字詞（例如「Google Chrome」→ ["google", "chrome"]）
  3. 驗證所有字詞是否都出現在某條 CPE 字串中
  4. 若 CPE 存在但完全不符 → 判定為可能誤判

判斷結果說明

判斷代表意義處置方式
符合CPE 條目確認與目標軟體相關納入版本分析與弱點統計
不符CPE 存在但不含搜尋名稱移至「可能誤判」區塊，不影響版本建議
無 CPE 資料CVE 無 CPE 設定資料，無法判斷保留（寧可保留以免漏報）
限制說明此機制仍可能有誤判或漏判。CPE 比對僅基於名稱字詞或識別碼，對於縮寫、別名、拼寫差異可能出現誤差。建議將報表結果搭配 NVD 連結人工複核重要項目。

程式使用 NIST NVD 提供的兩支 REST API，均為公開免費服務，無需帳號即可呼叫（但有 API Key 時速率限制較寬鬆）。

CPE 命名格式

CPE（Common Platform Enumeration）是 NIST 制定的標準化產品命名規則，格式為：

cpe:2.3:{type}:{vendor}:{product}:{version}:{update}:{edition}:...
  例：cpe:2.3:a:apache:maven:3.8.6:*:*:*:*:*:*:*
  例：cpe:2.3:a:7-zip:7-zip:24.09:*:*:*:*:*:*:*
  例：cpe:2.3:a:neo4j:neo4j:2025.05.0:*:*:*:*:*:*:*

程式如何使用回傳資料

  1. findAllCPEBases() 從最多 10000 筆結果中，依三輪規則找出所有符合軟體名稱的 {vendor, product} 組合（OR 邏輯）——同一軟體可能有不只一種 vendor 命名（例如 PuTTY 的 putty:putty 與 simon_tatham:putty）
  2. 找到的每個組合都會各自查詢 CVE，再依 CVE id 合併去重，確保不會只查到其中一種命名下的弱點
  3. 後續對每筆 CVE 驗證其 CPE 條目是否包含任一組合的 :vendor:product: 精確字串
  4. 若 CPE API 完全找不到對應識別碼，降級為一般關鍵字比對模式
為何 Portable 軟體要多一步 CPE 查詢？Registry 軟體的名稱（如 7-Zip 24.09 (x64)）通常足以辨識，但 Portable 軟體的名稱可能較短或有歧義（如只填 Maven）。先查 CPE 識別碼可避免把 Jenkins 的 Maven 插件 CVE 誤算為 Apache Maven 的弱點。

常見問題

Q：掃描速度很慢，可以加快嗎？

速度受 NVD API 速率限制影響。使用 API Key 可達到 50 req/30 s（間隔 0.7 秒），不使用 Key 只有 5 req/30 s（間隔 6.5 秒）。短期可用 LIMIT 參數限制掃描筆數，長期建議將大量固定廠牌加入 WHITELIST 白名單。

Q：出現「HTTP 404」錯誤怎麼辦？

最常見原因是 API Key 傳遞方式錯誤。NVD API v2 必須透過 HTTP Header apiKey: 傳送，不可放在 URL query parameter 中。若您修改了程式碼，請確認未將 API Key 加入 URLSearchParams。

Q：「可能誤判」的 CVE 還要手動查嗎？

「可能誤判」的 CVE 已被排除在版本分析之外，不會影響升級建議。每筆可能誤判項目都附有說明原因。若仍想確認，可點擊 CVE ID 連結前往 NVD，查看「Known Affected Software Configurations」確認受影響產品是否包含您使用的軟體。

Q：軟體找不到任何 CVE，是真的安全嗎？

不一定。NVD 的搜尋是關鍵字比對，若軟體名稱與 NVD 資料庫中的 CPE 命名不一致，就可能搜尋不到。建議：

  • 查看程式終端機輸出的 Search: "xxx" 欄位，確認搜尋字詞合理
  • 直接前往 NVD 搜尋頁面手動確認
  • 對於重要的免安裝軟體，改用 PORTABLE_N 設定，程式會自動透過 CPE API 查找精確識別碼

Q：狀態顯示「? 請手動確認」是什麼意思？

表示該軟體的 CVE 中，有部分尚未在 NVD 記錄修復版本資訊。即使目前安裝版本滿足其他 CVE 的修復要求，仍無法確認對所有 CVE 都安全。請點擊各 CVE 連結查看 NVD 最新資訊，確認是否已有新版本修復。

Q：為什麼有些軟體沒有出現在任何區塊？

Registry 中 DisplayName 為空的項目會被完全忽略，不列入任何統計。

Q：同一個軟體有多個版本怎麼辦？

去重邏輯是以清理版本號後的名稱為鍵，保留第一筆出現的條目，後續相同名稱的條目列在「重複去除的軟體」區塊。建議保留版本較新的軟體，移除舊版後重新掃描。

Web 掃描器 — 工具簡介

CVE Web Scanner 是一套純瀏覽器端的軟體弱點掃描工具，不需要安裝任何軟體，直接以瀏覽器開啟 web-client.html 即可使用。

功能與 Node.js 命令列版（cve-checker.js）相同：

  • 載入 scan.json（由 findSW.ps1 或 cve-checker.js 在目標機器產生）
  • 查詢 NIST NVD CVE API，依嚴重度、年份過濾
  • 比對建議修復版本，判斷升級狀態
  • 產出與 CLI 版格式相同的 HTML 視覺化報表及 JSON 結果
  • 查詢伺服器本機已快取的 CVE 資料（CVE 查詢頁籤，僅伺服器代理模式）

模式一：獨立瀏覽器模式（Standalone）

Web 掃描器 — CVE 查詢頁籤

切換至「🔍 CVE 查詢」頁籤，可直接查詢伺服器本機已快取的 CVE 資料——任何一次掃描（不論是哪一台電腦、哪個使用者執行的）查過的軟體，都會留在 data/ 目錄的本機快取中，不需要重新掃描即可查詢，也不會對 NVD 發出任何請求。

  • 輸入軟體名稱關鍵字（例：putty）或完整 CVE ID（例：CVE-2024-12345），至少 2 個字元
  • 可加上最低嚴重度、最早年份篩選結果（與檔案掃描的篩選邏輯一致）
  • 結果依快取項目分組顯示，每組標示對應的軟體/CPE 識別碼、CVE 筆數、快取最後更新時間
僅伺服器代理模式可用瀏覽器無法直接讀取伺服器本機的 data/ 目錄，因此此頁籤需先啟動 web-server.js（npm run web）才能使用。獨立模式（直接雙擊開啟 web-client.html）下會顯示提示訊息並停用查詢欄位。
資料來源的限制快取是以「曾經查詢過的軟體/CPE」為單位，不是以「已安裝版本」為單位，所以查詢結果不會顯示「目前安裝版本」或「是否需要升級」，僅顯示該軟體曾經查到的 CVE 清單本身。

「⚠ CPE 條目中未含...」的意義

程式對每筆 CVE 進行關聯性驗證，確認搜尋到的 CVE 是否真的與該軟體有關。若 CVE 的 CPE（Common Platform Enumeration）條目中未出現搜尋名稱，該 CVE 會被標記為可能誤判，顯示 ⚠ 警告，並列入報表的「可能誤判」區塊，不影響版本建議或升級狀態。

Web 掃描器 — 報表內容說明

Web 版產出的 HTML 報表與命令列版（cve-checker.js）格式相同，包含以下區塊：

  1. Header 儀表板：軟體總計、白名單略過、子元件/重複略過、實際掃描數；發現弱點數、CVE 總數、各狀態分類統計
  2. 升級建議摘要表：列出所有掃描軟體，顯示已安裝版本、最低安全版本、升級狀態
  3. CVE 詳細資訊：每個有弱點軟體的可展開區塊，包含 CVE ID 連結、嚴重度、發布日期、描述、安全版本、升級建議

Web 掃描器 — 常見問題

Q：出現「CORS 錯誤」或無法連線 NVD，怎麼辦？

這表示您的瀏覽器或網路環境封鎖了對 services.nvd.nist.gov 的直接請求。請改用伺服器代理模式：在有網路權限的機器上啟動 web-server.js，再以瀏覽器連線至該伺服器。

Q：上傳 scan.json 後顯示「JSON 格式錯誤」？

請確認 JSON 檔案中包含 softwares 陣列（findSW.ps1 或 cve-checker.js 產生的格式）。若是自行建立的 JSON 或其他工具產生的格式，可能不相容。

Q：掃描中途關閉瀏覽器分頁會怎樣？

獨立模式下掃描會直接中斷。伺服器代理模式下，伺服器會偵測到連線關閉並停止後續 API 查詢，Log 中會記錄「掃描取消（已完成 N/M）」。

Q：兩個頁籤可以同時掃描嗎？

不行。每次只能有一個頁籤進行掃描，掃描期間另一個頁籤的按鈕會停用。請等待當前掃描完成或取消後再切換。

Q：掃描完成後切換頁籤，報表還能開啟嗎？

可以。每個頁籤的報表連結獨立保存，切換頁籤不會影響另一個頁籤的報表。但若在同一頁籤重新執行掃描，前一次的報表連結會被撤銷。

Q：如何將 Web 版結果納入 team-report.js 彙整？

在「📁 檔案掃描(JSON)」模式掃描完成後，點擊「⬇ result.json」下載 JSON 結果，再將其複製至 team 目錄，搭配其他機器的 JSON 一起執行 node scripts/team-report.js 即可。

Q：CVE 查詢頁籤搜尋不到任何結果？

CVE 查詢只會從本機 data/ 目錄的快取中搜尋——也就是「以前曾經掃描過的軟體」才會有記錄。如果是第一次查詢某個軟體，請先到「📁 檔案掃描(JSON)」頁籤掃描過一次（或用 CLI 版掃過），之後才能在 CVE 查詢頁籤找到它。
